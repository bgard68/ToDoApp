Password verification and token issuance

// Infrastructure/Authentication/PasswordHasher.cs
SaltSize   = 16;        // 128-bit
KeySize    = 32;        // 256-bit
Iterations = 600_000;   // PBKDF2-SHA256

var attempt = Rfc2898DeriveBytes.Pbkdf2(
    password, salt, iterations, SHA256, key.Length);
return CryptographicOperations
    .FixedTimeEquals(attempt, key);
  • ✓Stored as iterations.salt.key. Older 100k-iteration hashes still verify and are re-hashed at 600k on next login (NeedsRehash).
  • ✓Constant-time compare, so timing doesn't leak how many bytes matched.
  • ✓Bad password or unknown user → same UnauthorizedException → 401. No user enumeration.
  • ✓TokenResponseFactory.Issue mints the access JWT and a refresh token. Only the refresh token's SHA-256 hash is persisted.

Authentication/AuthenticationSetup.cs

Validation: four framework checks, then one of ours

TokenValidationParameters = new()
{
  ValidateIssuer           = true,
  ValidateAudience         = true,
  ValidateIssuerSigningKey = true,
  ValidateLifetime         = true,
  ClockSkew     = TimeSpan.FromSeconds(30),
  NameClaimType = "sub",
  RoleClaimType = "role"
};
OnTokenValidated = async ctx =>
{
  var sub   = ctx.Principal.FindFirstValue("sub");
  var stamp = ctx.Principal.FindFirstValue("sstamp");

  var user = await db.Users.AsNoTracking()
      .FirstOrDefaultAsync(u => u.Id == userId);

  if (user is null || !user.IsActive
      || user.SecurityStamp != stamp)
      ctx.Fail("This token has been revoked.");
};

Any failure means HttpContext.User stays unauthenticated, and a protected endpoint returns 401 before the handler runs.

Authorization · three layers

Endpoint, row, role

// Endpoints/TodoEndpoints.cs
var group = app.MapGroup("/api/todos")
    .RequireAuthorization();   // default policy

// GetTodoByIdQueryHandler.cs
var entity = await _context.TodoItems
    .AsNoTracking()
    .FirstOrDefaultAsync(t => t.Id == request.Id
        && t.UserId == userId, ct)
    ?? throw new NotFoundException(...);
  • ✓Endpoint. RequireAuthorization() with no policy name applies the default policy, RequireAuthenticatedUser(). It covers the todos and categories groups, plus /logout, /revoke-all and /me.
  • ✓Row. Every handler filters by sub. A foreign id returns 404, not 403, so existence isn't disclosed.
  • ✓Role. User or Admin via the role claim. Checked in the handler: only an Admin may revoke another user's sessions, otherwise ForbiddenAccessException → 403.
  • ✓Anonymous: /register, /login, /google, /refresh.
POST /api/auth/refresh · RefreshTokenCommandHandler

Rotation with reuse detection

var token = await _db.RefreshTokens.FirstOrDefaultAsync(t => t.TokenHash == Hash(raw));
if (token is null || user is null || !user.IsActive) throw Unauthorized;

if (token.IsRevoked)                                    // already rotated → replayed → assume theft
{
    user.RotateSecurityStamp(now);                     // kill every access token
    await RevokeAllActiveTokensAsync(user.Id, "Refresh token reuse detected");
    throw Unauthorized;
}
if (token.IsExpired(now)) { token.Revoke("Expired"); throw Unauthorized; }

token.Revoke("Rotated", now, newRefresh.TokenHash);     // chain old → new
_db.RefreshTokens.Add(new RefreshToken(user.Id, newRefresh.TokenHash, ...));

Client consequence: single-flight refresh

When the access token expires, several calls 401 at once. If each one refreshed independently, the second would present an already-rotated token, trip reuse detection and sign the user out everywhere. apiClient.js shares one in-flight refresh promise.

Revocation

Making stateless tokens revocable

Security stamp

Kills access tokens instantly

Embedded as sstamp and compared on every request in OnTokenValidated. RotateSecurityStamp() invalidates all outstanding JWTs for that user, on every device.

Refresh-token store

Stops new access tokens

Hashed rows, individually revocable, with a reason and a replaced-by chain. Reuse of a revoked token triggers full revocation.

// POST /api/auth/revoke-all · RevokeAllTokensCommandHandler
if (targetUserId != currentUserId && !_currentUser.IsInRole("Admin")) throw new ForbiddenAccessException();
user.RotateSecurityStamp(now);
foreach (var t in activeTokens) t.Revoke("All sessions revoked", now);

Trade-off: one AsNoTracking primary-key lookup per authenticated request. That gives up pure statelessness in exchange for instant revocation and deactivation (IsActive = false).

docs/lessons.md · bugs that were invisible

Three findings worth knowing

IPv6 exempt from limiting

Hand-sliced port stripping turned [2001:db8::1]:51514 into a key that included the ephemeral port, so every connection got a new partition. The fix moved the logic into ClientAddress, parsed it properly and added 14 tests.

Whole site in one partition

TrustForwardedFor shipped false and wasn't provisioned. Behind App Service, everyone shared 10 logins a minute.

Sign-out everywhere

Parallel 401s each refreshed, and the replay tripped reuse detection. Fixed with single-flight refresh on the client.

Takeaway

A rate limiter has no failure signal. Working, wide open and throttling everyone all look the same from outside, so the partition key has to be reachable by tests.
